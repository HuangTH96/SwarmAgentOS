# 文档说明
该文档记录如何实现**通过Web端选择机型，通过虚拟摇杆控制飞行器运动，并在页面上查看飞行器状态和传回的画面** 。

当前实现三个机型，因此该文档分为三个部分：
1. DJI
2. Tello
3. PX4

# 1. DJI
功能说明：
**在Web端选择机型，通过虚拟摇杆控制DJI运动，并且页面上查看DJI状态和传回的画面**

该功能实际上是由三件事情组成，分成四条独立的通道，同时运行：
```
                     ┌──────────────────────────┐
                     │        网页 (前端)        │
                     └──────────────────────────┘
   ①选机型/看列表      ②摇杆控制         ③看状态数据       ④看画面
        │                 │                 │                │
   REST接口          controlSocket     controlWebSocket   直接连视频服务器
   (发一次问一次)      (专用摇杆通道)      (专用状态通道)      (不经过后端转发)
        │                 │                 │                │
        ▼                 ▼                 ▼                ▼
┌─────────────────────────────────────────────────┐    ┌──────────────┐
│              后端 (fastApiMSDK-UDP)              │    │  视频中转站   │
│   websocket_router.py  →  manager.py            │    │ (MediaMTX)   │
└─────────────────────────────────────────────────┘    └──────────────┘
        │                                     ▲                ▲
        │ UDP指令(发出去等确认)      UDP状态包(定期上报)          │ 推流
        ▼                                     │                │
┌─────────────────────────────────────────────────────────────────┐
│                          DJI 飞机                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 1.1 选机型
`/SwarmAgentOS/web/static/combined_script.js` 发送请求，询问后端`/SwarmAgentOS/web/manager.py` “哪些飞机在线”；后端按照记录的在线列表回答

## 1.2 摇杆控制
1. 网页打开时，构建并持续维护 `controlSocket` ，专门用来发摇杆动作；
2. 信号流：拖动摇杆 → 换算成数字 → 每0.1秒往这条线上发一次 → 后端 `websocket_router.py` 收到后转给 `manager.py` → `manager.py` 通过 UDP 真正发给飞机

## 1.3 查看状态数据
1. 网页里构建并持续维护了另一条独立的线：`controlWebSocket`，和`controlSocket`那条完全完全独立，互不知道对方存在，专门用来接收飞机状态。
2. 飞机每隔一小段时间主动把自己的位置、姿态这些信息用 UDP 发给`fastApiMSDK-UDP` 模块，也就是： \
    a. **`main.py`**：包含监听 UDP Port **`8081`** 数据包的程序：`UDPServerProtocol`。飞机把状态数据往这个端口发。\
    b. **`manager.py`**：`main.py` 收到数据包之后，转交给这个文件里的一个全局对象 `manager`，记录这架飞机的状态、判断它是不是还在线、再把状态通过`controlWebSocket`转发给网页。 
3. 网页收到后，如果正好是当前选中的这架飞机，就刷新界面上显示的数字。

## 1.4 查看实时画面
1. 飞机把画面推到一个专门做视频转发的服务`MediaMTX`
2. `MediaMTX` 仅起到牵线搭桥的作用：
    ```
    DJI飞机 --推流--> MediaMTX（视频转发服务，单独部署的软件）<--拉流-- 网页播放器
                        ▲
                        │ "牵线搭桥"（问一下画面地址在哪）
                   fastApiMSDK-UDP 后端
    ```

    a. **飞机那边**：把摄像头画面按照 `RTMP` 这种格式，推给 `MediaMTX` \
    b. **MediaMTX**：收下这路推流，等着有人来拉取 \
    c. **`fastApiMSDK-UDP` 后端**：网页问"我要看哪架飞机的画面"，后端去问 `MediaMTX` "这架飞机的画面地址是什么"，把地址告诉网页，自己不搬运画面数据 \
    d. **网页**：拿到地址后，直接找 MediaMTX 要画面，画面数据不再经过 `fastApiMSDK-UDP` 后端中转
